# 相对原项目的增强与 UI 变化

**原作者：saya-ch 及 dsh-mobile 贡献者。** 比较基线为本项目整合时的 [dsh-mobile](https://github.com/saya-ch/dsh-mobile) 源码，具体修订见 [来源记录](../../CREDITS.md)，
不把原项目后续版本或 DeepSeek Harness 本身的功能混在一起比较。

## 沿用的基础能力

电脑端 HTTPS 网关、设备配对、Cookie/Origin/证书约束、LAN/远程通道、网页适配、CLI 与 question-fixes 来自原项目，
原始发布归档和许可保留。DeepSeek Harness 提供会话、工作区、模型、工具、权限与代理执行等业务。
原项目通过 DSH 网页本来就能显示 Markdown、文件、工具等内容，这些不是本项目首次创造的能力。

本项目的基本原生页面见首页“功能与界面”截图：工作区、会话列表、消息、添加连接、插件列表及 diff。

## 核实的实现差异

### Android 容器 → 原生页面

原项目 `apps/mobile/README.zh-CN.md` 将 App 明确描述为 WebView 薄壳，读取同一 HTTPS DSH 前端。
本项目使用 `app/` 与 `core/` 的 Kotlin / Jetpack Compose 界面，工作区、会话、插件、设备和设置为原生组件。

UI 变化：从网页容器和原配对卡片，变成工作区主入口、原生消息气泡与紧凑过程行、原生设置区块和原生文件查看器。
[原作者公开截图](https://github.com/saya-ch/dsh-mobile#设备管理) 与
[本项目原生截图](../screenshots/README.md) 分别标明来源；不复制原截图中的背景插画或连接地址。

### 移动阅读和文件操作

本项目通过原生 Markdown 组件提供表格、代码复制/折行，完成后折叠过程；这些是移动呈现与交互调整。
文件卡片保留 DeepSeek Harness 的类型分类/图标基础，点击由本 App 打开内容、diff 或图片。
Markdown 的电脑文件路径由手机侧解析成受控的远端读取，不改写电脑文档。

UI：会话浅/深色、Markdown 控件、diff 截图。实现主要位于 app 的 Markdown、文件 UI 和 core/data 的附件读取器。

### 本地设备与状态

默认设备启动入口；同一电脑保存局域网和隧道连接，在家用局域网、在外用隧道，手动快速切换，无需重复添加设备；置顶仅本 App 生效，使用时长按设备/天记录前台时间，支持近 7 天柱状图。
缓存清理只清选中的本地状态，连接凭据保留；删除设备后的默认和路由一同更新。

UI：设备设置、使用时长、浅色设置截图。数据逻辑位于 LocalDeviceData 与 DeviceStore。
原项目也支持多设备和自身排序；不宣称多设备是本项目新增的底层网关能力。

### 通知、恢复与任务呈现

原生通知明确区分完成、提问、权限，前台同会话抑制重复提醒；待确认发送可核对、解除并重新获得输入控制。
活动任务管理、目标浮动栏的暂停/编辑/删除及状态同步使用原宿主和增强服务，不是另起一套电脑代理。

UI：权限组件、目标浮动栏、任务列表；华为后台限制仍需系统授权和真实手机验收，不夸称可靠系统推送。

### 主题、分支和用量

原生界面提供跟随系统/浅色/深色。Git 工作区显示当前分支，非 Git 不展示。
设备设置的三列用量从电脑凭据服务获取，累计消费依赖桌面账号登录；未知状态可解释。
这些是原生信息组织和增强接口，不能替代官方平台账单。

## 不保证覆盖原项目的全部网页扩展

原项目 `/mobile` CSS/JS 定制、网页侧栏扩展和网页语音桥接不会自动驱动原生 Compose 页。
本项目保留整合插件的网页入口，但原生客户端不是任意浏览器插件的兼容层。
各能力依赖、宿主固定模块校验和实际验证范围见 [版本兼容](../版本兼容说明.md)。
